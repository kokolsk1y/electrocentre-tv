# Управление эфиром

Cloudflare Worker обслуживает Telegram-бота, черновик и опубликованную очередь. Изменения в боте не меняют эфир до команды `/publish`. Будущая замена в том же месте переключается автоматически в заданное время. Окончание периода лишь помечает баннер как просроченный. Вся очередь остаётся в заданном сотрудником порядке.

## Адреса

- `GET /api/published` — действующий набор для телевизора.
- `GET /api/preview/:token` — только чтение черновика. Можно добавить `?at=2026-11-01T00:00:00%2B03:00`, чтобы увидеть запланированный набор на выбранный момент.
- `GET /media/banners/:uuid.webp` — опубликованные и черновые WebP из R2.
- `POST /telegram/webhook` — Telegram webhook с `X-Telegram-Bot-Api-Secret-Token`.

Ответ TV API: `{revision,draft,generatedAt,nextChangeAt,items:[{id,slot,position,kind,name,src?,templateId?,durationSeconds?,validFrom,validUntil,overdue}]}`. `items` уже содержит нужный объект для каждого места на момент запроса; клиент не рассчитывает чередование или повторы. `nextChangeAt` указывает ближайшее автоматическое переключение или `null`. Черновой ответ дополнительно содержит `schedule` с будущими версиями. `Cache-Control: no-store`; read-only API открыт по CORS для телевизоров с разных адресов. Управление доступно только через защищённый webhook Telegram.

## Запуск после передачи доступов

1. Создать D1 и R2 в Cloudflare. Скопировать `wrangler.example.jsonc` в `wrangler.jsonc`, вписать D1 ID, имена ресурсов, адрес GitHub Pages и разрешённые числовые Telegram ID. `wrangler.jsonc` не включать в Git.
2. Выполнить миграцию `schema.sql` в D1 и опубликовать Worker. Первый запрос автоматически заполнит D1 текущей очередью из `src/seed.js` (5 встроенных сцен, 7 роликов, 6 октябрьских баннеров).
3. Установить секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` в настройках Worker. Не сохранять их в репозитории. Назначить Telegram webhook `https://<worker>/telegram/webhook` с тем же секретом в параметре `secret_token`.
4. Ссылка предпросмотра содержит `?preview=TOKEN&api=WORKER_URL` и работает до подключения live API. После проверки указать базовый адрес Worker в `<meta name="tv-playlist-api">` рабочей TV-страницы. До этого основной эфир продолжает использовать старый статический порядок.
5. Проверить `/api/published`, Telegram `/draft`, предпросмотр, плановую замену, публикацию и показ на реальном телевизоре.

Изображение скачивается из Telegram только во время добавления. Вход ограничен 20 МБ. Cloudflare Images преобразует его в WebP с `quality=90` и шириной не более 1920 px; в R2 сохраняется только результат. Cloudflare Images не предоставляет параметр Pillow `method=6`; использование Cloudflare конвертации согласовано для этой функции. Старые R2 файлы удаляются не раньше 48 часов после ухода из обоих наборов. Плановая очистка запускается раз в шесть часов. Исходные октябрьские файлы находятся в GitHub Pages и не удаляются Worker.

В `/draft` бот показывает пронумерованный список, изображения и кнопки для замены, переименования, изменения срока, перемещения и удаления. При загрузке доступны быстрые периоды «Этот месяц», «Следующий месяц», «Бессрочно» и ручной ввод даты. `/discard` сбрасывает весь черновик после подтверждения.

Новый ролик пользователь размещает в `videos/` на GitHub Pages отдельно. Затем бот добавляет его в черновик командой `/addvideo имя.mp4` после проверки доступности файла. Видеофайлы бот не загружает.

Локальные тесты: `node --test` в папке `backend/`. Проверка Cloudflare bindings и Samsung TV требует настроенного аккаунта и устройства.
